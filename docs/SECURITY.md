# Security

Eclipse Crew runs AI agents that browse the web, read untrusted content and act on your behalf on your own machine. This document has two parts: the security requirements every contribution must meet, and how to report a vulnerability.

The design behind these rules is in [`docs/ARCHITECTURE.md` §15](ARCHITECTURE.md#15-security-architecture).

> These controls are layered mitigations, not guarantees. Prompt injection in particular is an unsolved problem. Run agents with the least permissions their job needs.

---

## Reporting a vulnerability

**Do not open a public issue for security problems.**

- Report privately through GitHub's **Security → Report a vulnerability** on this repository.
- Include affected version or commit, steps to reproduce, impact, and any proof-of-concept.
- We aim to acknowledge within 3 days and agree a disclosure timeline with you. Please allow a fix to ship before public disclosure.

**In scope:** sandbox escape, cross-agent access (one agent reading another's files, credentials or memory), secret leakage to the model, the browser or logs, authentication bypass, tripwire or egress-proxy bypass, receipt forgery, prompt injection that crosses task scope, and RCE through uploads, downloads or webhooks.

**Out of scope:** issues that need an already-compromised host or `.env`, a model simply giving a wrong answer, and attacks on third-party model providers or websites.

| Version | Supported |
|---|---|
| `main` (latest) | Yes |
| Older commits | No |

## Security requirements

The keywords **MUST**, **MUST NOT** and **SHOULD** are used as in RFC 2119.

### 1. Authentication

Eclipse Crew has owner-created accounts (ADR-037), one isolated workspace each, with no public signup.

- Every page, API route, SSE stream and WebSocket (including the noVNC desktop stream) **MUST** require a valid session for exactly one account. This includes the cost receipt, budget-attention poll and price settings routes; another account's (or an unknown) run, agent, chat, receipt, file or stream returns the existing 403/404, the same as an unknown id. The only exceptions are:
  - `/login`
  - `/setup`, and only until the owner account exists. After that it **MUST** return 404 permanently.
  - `POST /api/hooks/<id>`, which is authenticated by its per-hook secret token instead (see §6).
  - an unauthenticated health check that returns no data.
- Authentication **MUST** be enforced server-side, in middleware *and* inside each handler. Hiding UI elements is not access control.
- Passwords **MUST** be hashed with argon2id and never stored or logged in plain text.
- Session cookies **MUST** be `Secure` (when served over HTTPS), `HttpOnly`, `SameSite=Lax` or stricter, and backed by a server-side session record so they can be revoked.
- State-changing requests **MUST** have CSRF protection.
- Current setup/login require the exact canonical `APP_ORIGIN`; authenticated mutations additionally compare a session-bound CSRF token in constant time. Session identity is read from Postgres, never a caller's owner header/body. Local HTTP uses `eclipse_session`; HTTPS uses Secure `__Host-eclipse_session`. Ingress overwrites forwarding headers; native HTTP trusts them only from the exact ingress DNS peer.
- Setup **MUST** use the shared setup/login/reset transaction lock. Conflicting legacy setup races fail without deletion. Accounts are created only from the host CLI (`account:create --login <email>` with the password through private stdin, never as an argument); no HTTP route **MUST** be able to create an account. Password recovery (`reset-password --login <email>`) uses private stdin and atomically revokes only that account's sessions; other accounts keep working. The per-login lockout **MUST NOT** be bypassable using claimed IP headers, and an unknown email **MUST** take a dummy argon2 verify so timing reveals nothing.
- Login, 2FA and password-change endpoints **MUST** be rate-limited, with temporary lockout after repeated failures: per login (5 failures in 5 min lock that login for 15 min) plus a global ceiling (50 failures in 5 min lock everyone for 5 min) to cap password spraying.
- Changing the password or email **MUST** require the current password. A password change **MUST** invalidate all other sessions.
- If TOTP 2FA is enabled, the secret **MUST** be encrypted at rest, recovery codes **MUST** be stored hashed and single-use, and each code **MUST NOT** be accepted twice.
- The app **MUST** bind to `127.0.0.1` by default. Remote access goes through Tailscale or HTTPS (Caddy) only.
- A public demo instance gives each judge a separate account (no shared login) and no 2FA. It **MUST** use HTTPS, long random passwords, a throwaway VM with no personal data, a spend-capped model key per account, and be deleted or rotated after use. The README section tells judges not to enter real credentials.

### 2. Authorization

There are two levels: the owner over their data, and each agent over only what its job needs.

**Owner level**

- Every table carries `owner_id`. Every query **MUST** be scoped by the session's `owner_id` through the shared data-access layer. One account **MUST NOT** be able to list, read or mutate another account's agents, crews, chats, runs, receipts, memory, skills, routines, connections, model keys or budgets; the desktop **MUST** refuse cross-account agent operations (`owner_mismatch`) and the stream proxy **MUST** check the session's `ownerId`.
- Resource IDs from the client **MUST** be checked for ownership before use. They **MUST NOT** be trusted just because they exist.

**Agent level (need-to-know)**

- Agent permissions are **default-deny**: tools, domains, memory scopes, files, credentials and action types are allowed only if listed in `agent_policies` or `permissions`. Exception (ADR-036): `agent_policies.any_public_web = true` (the default for new agents) allows any **public** hostname at the egress proxy; private, loopback, link-local and metadata addresses stay blocked for every agent, and the owner can switch an agent back to an explicit site list.
- Isolation **MUST** be enforced by the OS, not the prompt. Each agent gets its own Linux user, home directory with mode `700`, screen and browser profile. There is no sudo and no access to other homes.
- v1 has no shared handoff folders (see Delegation below): a handoff copies only the stored owner message into the receiver's chat, so there is no cross-agent file surface to scope.
- Memory reads **MUST** respect scopes (`global`, `agent`, `private`). An agent **MUST NOT** see another agent's `private` entries or credentials.
- Sub-agents and handoffs **MUST NOT** get more permissions than their caller, and **MUST** inherit taint.
- "Always allow" grants **MUST** be scoped to agent + site + action (+ optional limit). They **MUST NOT** be global. Implemented: one active `permissions` row per agent + exact host + action class, default 20 uses in a rolling 24 hours; the owner can revoke it in agent settings. Grants never apply to another agent, host or class.
- Approval checks **MUST** look at action arguments, not only tool names. For example, `send_email` to a new recipient escalates. Implemented limit: a risky grounded click is classified by code from the control name and `expect` (download, send, post, delete, purchase, submit). Classification is heuristic—a page can label a destructive button neutrally—and an Enter key that submits a form is not classified. Replay never prompts: a risky replay step proceeds only with a live grant that has capacity.
- Astra Mode removes approval prompts only. Receipts, audit log, budgets, tripwire, token isolation and the block on out-of-scope data exfiltration after untrusted content **MUST** stay on. Implemented: `agents.astra_mode` changes only through `POST /api/agents/[id]/astra` with an explicit acknowledgement; the approval gate records `auto_allowed` and the step receipt carries `astra_allowed`. No other module reads the setting.

**Internal services**

- `desktop-controller`, Postgres, CDP, VNC and the job queue **MUST NOT** be published to the host. They live on the internal Docker network only.
- The `pgboss` schema **MUST** be created by migrations, owned by the migration role, and used at runtime with `migrate: false`/`reindex: false`. The app role gets schema usage plus queue DML, sequence and function execution only; it gets no schema creation, table ownership or DDL.
- `desktop-controller` **MUST** accept requests only from `app`, authenticated with an internal shared secret. Network placement alone is not enough.
- Both HTTP and WebSocket require the secret and exact current app DNS source; DNS failures deny access. Public upgrades require the exact canonical Host/Origin and a database-backed owner session. Revalidate within five seconds and terminate revoked/expired/replaced streams. Silent peers have bounded heartbeat teardown.
- VNC credentials **MUST** stay in private worker/controller memory and mode-600 runtime files. The authenticated browser receives only sanitized RFB pixels; server-side protocol filtering rejects keyboard/pointer/clipboard injection on the view-only channel. Owner input stays on separate authenticated, CSRF-protected HTTP routes.
- VNC startup **MUST NOT** put passwords in process arguments. The pinned x11vnc reads a mode-600 private tmpfs password file and removes it on read; `-nosel` disables selection/clipboard exchange on this screen stream.
- Lifecycle, takeover and operations **MUST** share one per-agent queue and recheck owner, UUID generation, running state and lease at dispatch. Acknowledged takeover blocks agent input/capture. Disconnect releases only its session/viewer lease. Uncertain input execution quarantines the session; never automatically replay it. A timed-out read (snapshot, page check, screenshot) executes nothing, so it reports `page_busy` and the session keeps running. A safety check that runs out of time refuses the input, which was not sent.
- Implemented (2026-11-03, changed 2026-11-05): takeover eligibility in the browser is a **UX policy only**. Take over and Hand back are one click each; the browser offers takeover only when an `(any-pointer: fine)` device is present, so touch-only devices stay view-only, and remote pointer forwarding accepts only `pointerType === "mouse"` events. It is not hardware attestation, never proof of attached devices, and never a server authorization boundary: the private view-only RFB channel and the existing owner/session/lease/CSRF guards on the input routes remain the authoritative enforcement. The check forwards nothing to the desktop and stores no key values.

### 3. Secrets

- Secrets **MUST NOT** reach client-side code. This covers API keys, provider tokens, the encryption key, signing keys, TOTP secrets, session secrets and OAuth tokens.
  - Never put a secret in a `NEXT_PUBLIC_*` variable.
  - Modules that touch secrets **MUST** import `server-only`.
  - API responses **MUST** return only the masked `key_hint` (e.g. `••••1a2b`), never the key itself, even to the owner after it has been saved.
- Implemented: tool tokens live in `connections`, encrypted with the master key, and are decrypted only to push them to the egress proxy over the private network. The proxy holds them in memory only, for one agent and up to four exact hosts, and injects them only where it can read the request (`/v1/tool-forward`, and the git gateway). A `CONNECT` tunnel never receives a credential, so a shell or browser cannot spend a tool token. The app never returns a token; views carry a masked hint. Blocking, tripping, deleting an agent or a policy expiry drops the entries. The proxy redacts the token, its base64 and URL-encoded forms from tool responses.
- Implemented: a GitHub App connection stores the `ghu_` access token and `ghr_` refresh token encrypted with ADR-027; both are decrypted only inside the app process to push credentials or refresh. The device code is encrypted at rest, single-use and never returned to the browser; the UI sees only the short user code, the link and the state. The app stores no client secret (only the public client ID and slug). Refresh runs in the app's pg-boss worker 30 minutes before expiry; a rejected refresh token marks the row `expired`, deletes the refresh token and stops injection. `POST /v1/github-device` is Bearer `EGRESS_PROXY_SECRET`, with a fixed host, two fixed paths, no redirects, a 15 s cap and a field allowlist; it cannot be used as a general outbound path. Disconnect deletes the row; GitHub-side revocation is a link to the owner's app authorizations because the revoke endpoint would need the client secret.
- Secrets **MUST NOT** reach the model. Provider keys and tool credentials are injected by the egress proxy, and **MUST NOT** appear in prompts, tool results, memory, skills or receipts. Implemented: `app` decrypts the saved key per request and sends it only to `egress-proxy` over the private `egress_app` network; the proxy adds it to one upstream call and never stores, logs or returns it. The proxy has no `ENCRYPTION_KEY` and no database access. It accepts only public HTTPS hosts and blocks private, loopback, link-local and metadata addresses.
- Local model servers (2026-11-05) use a separate route, `/v1/local-forward`, which **MUST** only connect to addresses on the owner's private network (RFC 1918, CGNAT `100.64.0.0/10` for Tailscale, IPv6 unique-local) and **MUST NOT** connect to loopback, link-local/metadata, multicast, public addresses or any subnet the proxy is attached to (the app, desktop and other Compose services). Only the app can use it (`EGRESS_PROXY_SECRET`); the desktop browser proxy and `/v1/forward` keep refusing private addresses. The target comes only from the owner's saved Settings → Models address or an owner-initiated Check server/Detect, never from a model, a page or a tool. A local server's optional key follows the same rules as any provider key (encrypted at rest, injected by the proxy, redacted from replies). A saved key **MUST NOT** be sent to a different destination: switching provider kind, server origin, or between Meta SAM and a local SAM server drops it unless the owner pastes it again.
- Passwords and OTPs typed for an agent **MUST** go through single-use, short-lived opaque handles that the executor resolves. They **MUST** be masked in screenshots and recordings and never persisted.
- Stored credentials **MUST** be encrypted at rest with the key from `.env`.
- `.env`, `data/` and backups **MUST NOT** be committed. `.gitignore` covers them, and CI **SHOULD** run a secret scanner.
- The desktop container **MUST NOT** mount `.env`, the database or any secret store.
- Logs and error reports **MUST NOT** contain secrets, session tokens, OTPs or full request bodies from auth routes.
- Each agent has its own canary secret (bait, not a credential). The app **MUST** check every `type` text before execution, including text split across steps and common encodings; the egress proxy **MUST** check the `CONNECT` host and plain-HTTP request line/headers before resolving or connecting. On a match the traffic **MUST** be refused, the proxy tripped, the agent's other runs cancelled, its desktop stopped, it paused with `security_stop`, and exactly one append-only `security_events` row recorded. The canary is encrypted at rest and the proxy receives only its SHA-256; no canary, matched text or host may appear in logs, cards, receipts or events. Implemented limits: HTTPS bodies/paths, chat text, owner takeover typing and provider calls are not inspected. The decoy `inbox/passwords-backup.txt` is planted once and is not recreated if deleted.

### 4. Database

- Postgres **MUST NOT** be published outside the Docker network.
- The app **MUST** connect as a least-privilege role, not the superuser. Migrations run with a separate migration role.
- Queries **MUST** go through Drizzle's parameterised query builder. Raw SQL built by string interpolation **MUST NOT** be used. Where raw SQL is unavoidable, it **MUST** use the parameterised `sql` template.
- The audit log, receipt tables, `cost_entries` and `security_events` are append-only. The app role **MUST NOT** have `UPDATE` or `DELETE` on them. Implemented: `audit_log` and `memory_versions` are append-only for `eclipse_app`; `memory_entries` may be updated (current state) but not deleted; `memory_changes` may be decided once. `model_prices` is owner-editable through the authenticated settings route; price changes never rewrite an existing cost row.
- Sensitive columns (`providers.encrypted_key`, `connections.encrypted_token`, `connections.encrypted_refresh_token`, `github_device_flows.encrypted_device_code`, `traveller_profiles.encrypted_blob`, TOTP secrets) **MUST** be encrypted at the application layer before storage.
- Owner scoping lives in the data-access layer (§2). Postgres row-level security **SHOULD** be added when multi-user team mode is introduced.
- Backups **MUST** be encrypted before they leave the machine.

### 5. Input

All input is untrusted until validated. This includes model output and anything an agent reads.

- All user input **MUST** be validated server-side with Zod schemas. Client-side validation is a UX convenience only.
- Model output is input too. Chat cards (`message`, `clarification`, `tool_connection`, `routine`) and action intents (`{action, target, expect}`) **MUST** be schema-validated before they are used. Invalid output is rejected and never executed.
- The page control list used for grounding (`page.snapshot`) is `web` data: names are length-limited and stripped of control characters, validated in the worker and again in the app, and shown to the model as names only, never coordinates. Password, one-time-code and other secret-looking fields and all field values are never listed, so they cannot be offered for clicking or typing by name.
- Every piece of content **MUST** carry a source tag. Only `user` content may instruct an agent. `web`, `email`, `document` and `tool` content is data only, and may change *how* a task is done, never *what* the task is.
- Implemented: one exported tag list (`user/agent/web/email/document/tool`) is validated on every model request; a missing or unknown tag is rejected before the provider is called. Only the owner's task part is `user`.
- Implemented rule (ADR-039): for any-public-web agents the task-scope typing check accepts any public domain (never IP literals or internal names); emails stay owner-named. "Only these sites" agents keep the owner-named rule.
- Implemented: task scope is computed in code from the owner's task, the agent's `domains` allowlist and the first readable page host. A `type` is refused when it names a host outside that scope, an email the owner did not name, or runs on an out-of-scope page unless the whole text is one allowed URL. The refusal sends no desktop input, writes a blocked receipt and one `security_events` row, and the second refusal stops the run as `scope_blocked`. The check does not see where a click, key press or form submission goes, and owner takeover typing is not checked; the egress allowlist is the network-level backstop. Astra Mode and approvals never override scope.
- Ingested untrusted content **SHOULD** pass through the quarantined reader (a tool-less model call that returns structured data) and the injection scanner.
- Memory writes **MUST** be injection-scanned. Untrusted-origin writes to shared memory **MUST** require approval. Implemented: agents can only add, and only within their saved memory scopes. Every request is NFKC-normalised, scanned for hidden text, markup, instruction-like phrases and secret shapes, and stored as pending; a rejection creates no row and no card. The owner reviews an escaped diff and approves or rejects; approval applies the stored text unchanged in one transaction. Add-only, the scanner and the diff are controls, but the owner's approval is the real one: a paraphrased injection that passes the pattern list still needs that click.
- Imported skills **MUST** be scanned and **MUST NOT** grant permissions.
- Generated skills are model output: the app validates a closed structured draft, renders `SKILL.md` itself, keeps drafts non-callable, and requires an explicit owner approval that grants no permissions. Approval copies only manifest-listed after-shots into the skill namespace, then deletes the capture's private artifacts; a failed cleanup leaves the skill non-callable.
- Outbound URLs chosen by an agent **MUST** pass the egress allowlist. Internal, loopback, RFC 1918 and cloud-metadata addresses (e.g. `169.254.169.254`) are always blocked.
- Text rendered in the UI **MUST** be escaped. Markdown from agents or web content **MUST** be sanitised, with no raw HTML and no `javascript:` URLs.
- Shell commands built from input **MUST** use argument arrays, never string concatenation.

### 6. APIs

- Every route handler **MUST** validate path params, query string and body with Zod. Object schemas **SHOULD** use `.strict()` to reject unknown fields.
- Request bodies **MUST** have size limits. Uploads have their own limit (§7).
- IDs **MUST** be validated for format (e.g. UUID) and then for ownership (§2).
- Responses **MUST NOT** leak stack traces, SQL errors or internal paths in production. Errors are logged server-side with a correlation ID.
- Mutating endpoints **MUST** use non-GET methods and be CSRF-protected.
- Webhooks (`POST /api/hooks/<id>`):
  - **MUST** require a high-entropy per-hook secret, compared in constant time.
  - **MUST** be rate-limited and size-limited.
  - Payloads are untrusted content (`source_tag = tool`) and **MUST NOT** be treated as instructions.
  - **SHOULD** verify provider signatures when available (e.g. GitHub `X-Hub-Signature-256`).
- Sensitive and costly endpoints (auth, Run Now, model Test, voice) **MUST** be rate-limited.
- CORS **MUST** stay same-origin only. No wildcard origins.
- Security headers **MUST** be set: a restrictive `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `frame-ancestors 'none'` (except the internal desktop view), and HSTS when served over HTTPS.

### 7. File uploads and downloads

This applies to chat attachments, Files tab uploads, and files agents download in the browser.

**File type**

- Type **MUST** be detected from content (magic bytes), not the extension or the client-supplied `Content-Type`.
- Documents, images, text, CSV/JSON, code, audio and video are allowed. Executables, scripts, installers, APKs and macro-enabled Office files are blocked by default.
- Implemented rule: content decides, the extension only blocks. Blocked by content: ELF, PE, Mach-O, Java class, DEX, legacy OLE2 Office (macros cannot be ruled out), `#!` scripts, ZIP-based APK/JAR, OOXML with `vbaProject.bin`, ODF with `Basic/` or `Scripts/`. Blocked by name: `.exe .dll .msi .bat .cmd .ps1 .vbs .wsf .hta .scr .lnk .sh .apk .jar .docm .xlsm .pptm` and similar. Other source code (for example `.py`, `.js`) is accepted as plain UTF-8 text. Also recognised by content: BMP, TIFF, ICO, HEIC/AVIF, WMV/ASF, FLV, MPEG, AIFF and MIDI; a text file that only starts like one of these stays text. Unknown binary content is refused. Archives are stored as opaque files and never extracted. A ZIP64 or unreadable Office-type container is refused.
- Archives **MUST** be checked for path traversal (zip-slip) and decompression bombs before extraction.

**File size**

- The per-file limit defaults to 250 MB (`MAX_UPLOAD_MB`, 1 to 1024), enforced while streaming, before the file is fully written. The upload route is excluded from `proxy.ts` (Next would buffer 10 MB and cut the rest), so it checks owner, Origin and CSRF itself, and the writer refuses any body that is shorter or longer than the declared `Content-Length`. At most one upload per agent and two across the stack run at a time.
- The per-agent storage quota defaults to 10 GB: warn at 80%, pause writes at 100%.

**Filename**

- Filenames **MUST** be normalised (Unicode NFC) and stripped of path separators (`/`, `\`), `..`, null bytes and control characters.
- Leading dots and Windows reserved names (`CON`, `NUL`, …) **MUST** be rejected.
- Filenames **MUST** be limited to 255 bytes. Collisions are resolved by suffixing, never by overwriting.
- The final path **MUST** resolve inside the target agent's `inbox/`, checked after resolving symlinks.

**Storage and handling**

- Uploads **MUST** be written as the target agent's Linux user, into that agent's `inbox/` only.
- `Downloads/` **MUST** resolve to the canonical `/downloads/<agent-uuid>` on a `noexec,nosuid,nodev` mount. Its persistent backing path `/workspace/.system/downloads` stays behind root-only `.system`; validate the home alias and reject substitutions. `noexec` blocks direct execution, not interpreter use or copying elsewhere. Agents **MUST NOT** run downloaded files without approval, and Office macros are disabled.
- Downloads **SHOULD** be checked by SHA-256 hash against MalwareBazaar. Only the hash is sent, never the file.
- File *contents* are untrusted data (§5), even when the owner uploaded the file.
- Implemented rule: agent file tools run only as the agent's Linux user on plain-named, regular, single-link files opened with `O_NOFOLLOW`; reads are limited to `inbox/` (documents 50 MiB, images 4 MiB, 20,000 characters per window), deliveries only from `Downloads/` and `work/` into `outbox/` with the upload block list plus extension/content matching. Extracted text and file names are `document`/`tool` tagged untrusted data; nothing is executed. Delivery is a deliberate action (never automatic) and the final message names every delivered file.
- Implemented rule: a memory change applies without the owner only through the origin gate. Code requires `memory_mode = auto`, a quote of at least 12 characters that is an exact substring of one of the owner's own `user` messages, at least 90% of the change's content words in that message, an allowed scan verdict, and a non-pinned target. Everything else waits for approval. Web, email, document and tool content is never `user` content, so it can never satisfy the gate. Pinned entries are never changed by an agent. Auto-saved changes are `trusted`, versioned, audited and undoable. Background review/tidy are owner-scoped, token-capped, budget-checked and may only merge/shorten/archive when 95% of the new words come from the sources; a tidy batch is undoable as a whole. `search_history` is scoped to the calling agent's own chat and returns data-tagged snippets.
- Implemented rule: extracted values are web data, held in run memory only (at most 10, each at most 2,000 characters) and never written to the database, receipts, checkpoints or logs. They are canary- and scope-checked before saving, and again after `{{name}}` is filled into typed text, so a page cannot smuggle a host or the canary through a saved value. `navigate` accepts only `http(s)` without credentials and goes through the typed-URL scope check; `select` only reads the option the model names and is grounded by code. Payment frames are never listed or controlled; a sensitive (password/OTP/card) frame's text never matches a page-text check. Closed shadow roots are a hand-off, never guessed at.
- Implemented rule: document search uses the same `read_document` permission and returns passages, never more than the read tool. The derived index lives only in the agent's `~/.cache/eclipse/doc-index/` (0700/0600), is tied to the file's SHA-256 and size, is parsed with a strict bounded schema, and is never listed, delivered, checkpointed, restored or readable by another agent. Office members are read by fixed name with `unzip -p` (20 s, 40 MB per member); XML is tag-stripped with a bounded entity table, never a general parser. Search results are `document`-tagged data; receipts and checkpoints keep the file name, query length and hit count only, never the query or passage text.
- Implemented rule: the agent's `outbox/` is read only as the agent's Linux user. Only regular, single-link files with a plain name (no separators, controls or leading dot) are carded or served; symlinks, directories, scripts by name and unknown binaries never are. A download is always `Content-Disposition: attachment` with `application/octet-stream`, `nosniff` and a `sandbox` CSP (the proxy applies a `default-src 'none'; sandbox` CSP to every `/api/*` answer), and the desktop re-checks size and SHA-256 against the card before the first byte. "Open on the agent's desktop" opens only `image` (not SVG), `pdf`, `audio`, `video` and plain `text` files whose extension matches (`.txt .md .csv .json .log` for text), in a new tab of that agent's own browser, never during a takeover. HTML, XML, SVG, Office files and archives are download-only. Residual risk: a file can still change between the hash check and the end of the stream; the owner downloads what the agent wrote.
- Previews in the web app **MUST** be served with `Content-Disposition` and `nosniff`, and from a sandboxed context for HTML, SVG and PDF, so an uploaded file can't run script in the app's origin. Implemented rule: inline chat previews (`/api/agents/:id/files/:messageId/preview`) serve only image (PNG, JPEG, GIF, WebP; never SVG), audio (MP3, WAV, OGG, M4A) and video (MP4, WebM) cards whose extension matches their kind, with an explicit type, `Content-Disposition: inline`, `nosniff` and a `sandbox; default-src 'none'` CSP; inbox reads run as the agent's Linux user with the same size and SHA-256 check as outbox downloads.

### 8. Sandbox, network and browser

- Containers **MUST** run as non-root with Docker default AppArmor, no `--privileged`, and read-only system paths where possible, except the owner-approved trusted desktop setup/supervisor role in ADR-026, which runs under the enforced `eclipse-desktop` AppArmor profile (docker-default plus only its four bootstrap mounts, ADR-038). Seccomp **MUST** remain Docker default except for the pinned desktop profile retained from ADR-025.
- Desktop **MUST** keep cap-drop ALL, no-new-privileges, read-only root, isolated networks and unpublished ports. Its profile is derived from pinned Playwright 1.64.1 plus only the chroot operation required within Chromium's private user namespace (applied SHA256 fa1e603f170044c931a103bfbe3bac6cfc6c935bdc72408e01c4cf6425cde627). Kernel checks must still deny ordinary outer-process chroot. Chrome's namespace/PID/network and Seccomp-BPF sandbox status must be verified in the smoke test. Never substitute seccomp=unconfined, capabilities beyond ADR-026 or --no-sandbox.
- ADR-026 permits only CHOWN/DAC_OVERRIDE/SETUID/SETGID/SETPCAP/SYS_ADMIN for trusted bootstrap. Before normal operation, PID 1 and every administrative entry point **MUST** permanently drop SYS_ADMIN (including bounding), install the inherited post-setup mount/privileged-syscall filter with ABI guards, and retain only the other five capabilities. No untrusted process runs before reduction succeeds. Every agent **MUST** run as its assigned UID/GID with no supplementary groups, all capability sets zero and no-new-privileges.

## Network and shell rules (2026-11-02)

- Every agent session runs in its own user+network namespace with only `lo`; the supervisor relay is the only exit and injects the egress token outside the namespace. A session that cannot create the namespace, socket or relay does not start. Verified live on Docker Desktop (loopback only; peer/controller/egress loopback refused). A minimal kernel/AppArmor probe on Oracle Ubuntu 24.04 aarch64 (AppArmor enabled, `kernel.apparmor_restrict_unprivileged_userns = 1`) passed with the project seccomp profile and the default AppArmor profile, and failed with `apparmor=unconfined`; the full isolation suite with the real x86-64 desktop image is still required. Never run the desktop container with `apparmor=unconfined`: on Ubuntu 24.04 user namespaces then fail before the session starts.
- A shell command runs as the agent user inside that namespace, with no token in its environment, fixed proxy variables, a 60 s default (600 s max), per-uid limits, capped output and its own process group. Output is `tool`-tagged untrusted data. Receipts keep the program name, command SHA-256/byte count, cwd, exit and timeout only. Compressed git pack data and the shell's own home are not scanned; there are no cgroup or disk quotas. The image adds `python3-venv`, `python3-pip`, `ripgrep`, `jq`, `patch`, `procps`, `zip` and `file` to the pinned offline package lock (445 archives / 250,231,110 bytes); `pip` installs only inside a venv (Ubuntu's system-wide PEP 668 block stays), no compiler or `python3-dev` is added, and the live check kept the 4 GiB `ulimit -v` cap because Node, WebAssembly and npm pass under it. Only agents whose Actions include `shell` get the larger 1,500,000 weighted-token / 60-minute tier; every other run uses the base of 60 steps / 400,000 weighted tokens / 30 minutes.
- Git over HTTPS goes through the 4322 gateway, never a TLS tunnel: the supervisor relay writes the agent's preface, the gateway verifies that HMAC and the agent's allowlist, strips any client `Authorization`, and reads receive-pack pkt-lines before forwarding. The gateway accepts the address-bar repository path with or without `.git`, forwards clone/fetch (`info/refs?service=git-upload-pack`, `git-upload-pack`) with no credential when the agent has no GitHub connection, and still requires the Basic `github.com` binding for both receive-pack requests. An upstream `401` becomes a fixed `403 credential_required` and no `WWW-Authenticate` header reaches the agent. Default-branch pushes, remote deletes and tag moves return 403 and create pending records until the owner grants them. Chunked bodies are refused; pack data is compressed and not canary-scanned. The token never enters the shell's environment or args, and nothing the agent sends can choose its gateway identity.
- Push approvals are memory-only and fail closed. A pending is bound to `(agentId, lowercase owner, lowercase repo, requestHash, ref, kind, old, new)`, where `requestHash` covers every ref command in the receive-pack request, including unprotected refs; a changed object id, ref, repo or command list needs fresh consent. Caps are 8 pending and 8 unused grants per agent plus 256 of each globally; pending lives 15 minutes and a grant 10 minutes. Issuing a grant removes its pending and is idempotent without renewal; every required grant is checked and consumed together immediately before forwarding, so a partial request forwards nothing and concurrent retries have one winner. Deny clears the whole request group. Policy block, trip, agent removal, policy expiry, grant revocation, run completion/cancellation and a proxy restart invalidate the records; expiry is the fallback when cleanup fails. The app reaches these controls only over the internal network with `EGRESS_PROXY_SECRET` (`GET /v1/pending`, `POST /v1/grants`, `DELETE /v1/pending/{id}`, `DELETE /v1/grants`, `DELETE /v1/git-approvals`); browser cookies and agent-supplied identities are never accepted. The model never receives pending ids or grants. Receipts keep the existing shell command hash/size fields and distinguish a blocked push, the approval decision and the later execution; grant issuance waits for the decision receipt to be stored. Pack bodies and the agent home remain unscanned, and there are no per-agent disk or memory quotas.

## Delegation, handoff and background helpers

- **Only the owner gives orders.** A handoff receiver's task is a copy of the stored owner message (`role = user`) by id, read fresh from the database; the sender's note is one `agent`-tagged line of data. A model cannot create a task, and a run that was not started from a stored owner message cannot hand off.
- **No privilege borrowing.** The receiver uses only its own permissions, site allowlist, connections, budget and Linux identity. Handoff copies no approvals, grants, saved values or memory.
- **Crew-only handoff (ADR-036).** An agent can hand off only to a crewmate (starter crew or an owner-created crew). A standard agent is never offered handoff and is refused with `not_in_crew`; a different crew gets `different_crew`. Owner `@Name` routing is the only cross-crew path.
- **Bounded delegation.** Handoff is refused after two hops, back to an agent that already had the request, to itself, or to a paused/busy teammate. A refusal tells the sender and does not stop its run.
- **Helpers never gain access.** `spawn_subagent` is off by default, limited to 3 one-level helpers, and every child action and tool is computed from the parent's grants and re-checked on each step. Helpers cannot use the desktop, screen lock, takeover lease, memory, handoff, `ask_owner` or nested spawn. A helper's risky call goes to the parent agent's approval gate and grant counts; its card names `Helper N`.
- **Helper output is data.** At most 4,000 characters of a helper summary reach the parent tagged `tool`; the parent must check it before acting. Scope checks use the owner's original task, never the helper's model-written task.
- **Cancellation and crash safety.** A cancelled parent cancels its helpers in process and through `cancel_requested_at`; the sweeper seals orphaned helpers `interrupted` with its normal `signature IS NULL` guard. Helpers and receivers have heartbeats like any run.
- **Proof.** The sender seals `handed_off`; the receiver header carries `handoff_of`; a helper header carries `parent_run`/`parent_step`; each is a separate signed run that verifies offline. Optional header fields are never written when absent, so old exports stay byte-identical.
- **Sweeper.** It signs with the existing install key, has no new grant, acts only after a 3-minute heartbeat gap, never touches a run with no heartbeat, and can be switched off with `RUN_SWEEPER_ENABLED=false`.
